# 中烟国际集团网站 - 新增新闻标准流程

> 本文档定义向“公司动态/新闻资讯”栏目新增一条新闻的标准流程和强制规则。以后收到用户提供的 `.docx` 新闻文件时，必须先阅读本文件，再开始修改代码。

---

## 1. 输入材料

用户通常会提供一个 `.docx` 新闻稿，内容一般包含：

- 标题：通常为首行或文档主标题。
- 日期：可能写成“X月Y日”“YYYY年X月Y日”等形式；年份不明确时，需要结合新闻内容和用户说明判断，无法确定时先确认。
- 图片：一张或多张，优先从 `word/media/image*.png`、`.jpg`、`.jpeg` 中提取。
- 正文：多段文字，按自然段拆分；不要把整篇正文塞进一个字段。

## 2. 新增前必须先盘点

新增前先读取 `i18n/locales/zh-CN.json` 和 `i18n/locales/zh-TW.json`，确认当前编号：

- `newsList` 中最大的 `id`，新新闻 `id = max_id + 1`。
- `message.newsTitle` / `message.newsTitle<N>` 的最大编号，新标题使用下一个编号。
- `message.newsContent` / `message.newsContent<N>` 的最大编号，新正文从下一个编号开始，每个自然段递增一个编号。
- 当前首页 `newsListIndex` 必须只有 3 条，新增后仍保持 3 条。

当前代码中曾出现过新闻 `id` 与 `newsTitle<N>` 编号不完全相同的情况，因此不要凭感觉写编号，必须以 JSON 实际最大值为准。

## 3. 必须修改的 4 个位置

| 序号 | 文件/目录 | 修改内容 |
|---|---|---|
| 1 | `i18n/locales/zh-CN.json` | 在 `newsList` 中按日期倒序插入新条目 `{ id, date, title, desc }`；把 `newsListIndex` 整体替换为最新 3 条；新增 `newsTitle<N>`；新增 `newsContent<N>` 到 `newsContent<N+M>`。 |
| 2 | `i18n/locales/zh-TW.json` | 与简体一致，标题、摘要、正文转换为繁体；标题引号按繁体习惯处理，不能留下未转换的简体段落。 |
| 3 | `src/views/newsDetail.vue` | 为新 `id` 增加详情页分支，包括标题、日期、图片和正文段落引用。标题引用 `$t('message.newsTitle<N>')`，正文引用对应的 `newsContent` 字段。 |
| 4 | `src/assets/images/newsPic/` | 保存新闻图片，建议命名为 `YYYYMMDD.png` / `YYYYMMDD.jpg`；同日多图使用 `YYYYMMDD_1.png`、`YYYYMMDD_2.png` 等后缀。 |

## 4. 强制规则

### 4.1 首页新闻永远只保留 3 条

首页新闻卡片来自 `newsListIndex`，新增新闻后必须整体替换为最新 3 条：

- 新新闻放在第一条。
- 其后保留日期最新的两条旧新闻。
- 绝对不要因为新增新闻把 `newsListIndex` 变成 4 条或更多。

### 4.2 新闻列表按日期倒序

`newsList` 用于新闻列表页，新增条目按日期倒序插入。不要只按 `id` 排序，因为旧数据里可能存在补录新闻。

### 4.3 标题要适合首页卡片

首页和列表页标题已经通过 CSS 做了单行省略：

```css
white-space: nowrap;
overflow: hidden;
text-overflow: ellipsis;
```

因此新增新闻标题需要控制长度：

- 标题首选控制在 20-25 个汉字左右。
- 人名、活动名、奖项名、地点、关键数字必须保留。
- 删除“正式”“圆满”“成功”“传递温暖力量”等可有可无的修饰词。
- 详细背景放入 `desc` 或正文，不要全部堆在标题里。

### 4.4 日期格式统一

- JSON 和详情页统一使用 `YYYY-MM-DD`，例如 `2026-06-11`。
- 如果 docx 只写“6月11日”，不能机械使用当前日期年份；要结合新闻稿内容、图片命名、用户说明和已有新闻时间线判断。
- 遇到跨年或年份不确定，先向用户确认。

### 4.5 图片命名和引用

- 图片文件放入 `src/assets/images/newsPic/`。
- 推荐文件名：`YYYYMMDD.png`、`YYYYMMDD.jpg`、`YYYYMMDD_1.png`。
- `newsDetail.vue` 中按现有项目写法引用相对路径，例如 `../assets/images/newsPic/20260614.png`。
- 多图新闻按正文顺序插入，图片说明单独作为正文段落或图片下方文字，不能丢失。

### 4.6 简繁对应

- 简体数据写入 `zh-CN.json`。
- 繁体数据写入 `zh-TW.json`。
- 繁体建议使用 OpenCC `s2tw` 转换后人工快速核对。
- `newsList.desc`、`newsListIndex.content`、`newsTitle`、`newsContent` 都要同步转换。

### 4.7 新闻内容必须以 docx 原文为准

- 标题、日期、图片说明、正文内容必须直接依据用户提供的 docx 原文添加。
- 不允许自由发挥、润色扩写、补写背景、添加总结句或改写新闻事实。
- 如标题过长影响首页展示，只能先向用户确认是否压缩，不能擅自改标题。
- 除错别字、明显格式符号、段落拆分、简繁转换、图片路径等必要技术处理外，不改变新闻原意和信息量。
- 如果 docx 内容缺少日期、图片说明或正文关键信息，应先询问用户确认，不要自行补充。

## 5. 不要修改的位置

| 文件/位置 | 原因 |
|---|---|
| `i18n/locales/en.json` | 英文版目前没有完整新闻数据，首页新闻区域在英文下隐藏。 |
| `src/views/IndexView.vue` | 首页新闻读取 `i18n.message.newsListIndex`，通常不需要改页面代码。 |
| `src/views/news.vue` | 新闻列表读取 `i18n.message.newsList`，通常不需要改页面代码。 |
| `src/router/index.js` | `/newsDetail/:id?` 已存在，新 `id` 可自动匹配。 |
| `src/views/components/SiteSearch.vue` | 站内搜索模块名来自导航文案，新增普通新闻不需要改搜索组件。 |
| `src/views/NewView.vue` | 旧页面/未挂载页面，不作为新增新闻入口。 |

## 6. 新增后必须验证

新增完成后至少验证以下页面：

1. 详情页：`/newsDetail/<新id>`，标题、日期、图片、正文全部正常。
2. 列表页：`/news`，新新闻位于合理位置，日期和摘要正确。
3. 首页：`/index`，新闻区域仍然只有 3 条，且新新闻在首位。
4. 繁体：切换繁体后首页、列表、详情三处正常显示。
5. 英文：切换英文后新闻区域行为与现有逻辑一致。

同时检查：

- 浏览器控制台没有新增红色报错。
- dev server 没有编译错误。
- `npm run build` 可以通过。
- `git diff` 中只包含本次新闻相关变更和必要图片。

## 7. 快速核对清单

```text
i18n/locales/zh-CN.json      newsList +1 / newsListIndex 保持 3 条 / newsTitle +1 / newsContent +N
i18n/locales/zh-TW.json      同步繁体数据
src/views/newsDetail.vue     新增对应 id 的标题、日期、图片、正文分支
src/assets/images/newsPic/   新增新闻图片，命名清晰
```

## 8. 给 Codex 的执行要求

以后用户给 `.docx` 新闻稿并要求新增新闻时，第一步必须打开并遵循本文件。执行顺序为：

1. 读取本流程文件。
2. 解析用户提供的 docx，提取标题、日期、图片、正文。
3. 盘点当前 JSON 和详情页编号。
4. 修改简体、繁体、详情页和图片资源。
5. 运行格式/构建/页面验证。
6. 汇报新增的 `id`、标题、日期、图片文件、验证结果。

不要跳过编号盘点，不要只改简体，不要让首页新闻超过 3 条。
