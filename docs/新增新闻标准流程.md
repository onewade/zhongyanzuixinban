# 中烟国际集团网站：新增新闻与环境发布流程

本文档用于规范后续新增新闻、演示部署、生产部署的操作方式。换电脑后只要拉取 Gitee 代码，也能同步看到这套规则。

## 一、三套环境的用途

| 环境 | 分支 | 用途 | 部署地址 |
|---|---|---|---|
| 本地开发 | `develop` | 日常修改、先给本地看效果 | `http://localhost:10087` |
| 演示环境 | `release` | 给客户确认，允许包含待确认功能 | `http://180.76.235.116:5177` |
| 生产环境 | `main` | 正式线上版本，只能包含确认上线的内容 | `http://103.107.88.249/` |

核心原则：

- `main` 永远代表生产真实版本。
- `release` 可以比生产新，用于客户演示。
- 生产不要直接整包合并 `release`。
- 如果只上线一条新闻，只把这条新闻相关提交挑到 `main`。
- 不要把演示环境里的无关功能误带到生产。

## 二、新增新闻时的标准流程

### 1. 先只改本地

收到新的新闻 Word、图片或正文后，先在本地处理。

通常只允许修改这些位置：

- `i18n/locales/zh-CN.json`
- `i18n/locales/zh-TW.json`
- `src/views/newsDetail.vue`
- `src/assets/images/newsPic/` 中新增图片文件
- 必要时更新 `年度更新记录.md`

不要因为新增新闻去改这些功能：

- 首页轮播控制
- 返回顶部按钮
- 跳至内容按钮
- 页面整体样式
- 导航、页脚、集团概况等无关页面

### 2. 本地验证

本地至少检查：

- 首页新闻区是否显示新标题、摘要和日期。
- 新闻列表 `/news` 是否有新新闻。
- 新闻详情 `/newsDetail/<id>` 是否能打开。
- 简体、繁体内容是否一致。
- 如果有图片，图片是否正常显示。
- `npm run build` 是否通过。

### 3. 提交到开发分支

本地确认后，提交到 `develop`。

推荐提交粒度：

- 一条新闻作为一个独立提交。
- 如果后续只修这条新闻摘要、正文位置，也作为独立提交。
- 不要把无关样式、无障碍功能、环境配置混进同一个提交。

## 三、部署到演示环境

当用户说“部署演示”“给客户看”时：

1. 将 `develop` 合并到 `release`。
2. 推送 `release` 到 Gitee。
3. 演示服务器拉取 `release`。
4. 执行演示部署脚本。
5. 检查演示地址：
   - `http://180.76.235.116:5177/`
   - `http://180.76.235.116:5177/newsDetail/<id>`

演示环境可以包含：

- 新新闻。
- 待确认的无障碍优化。
- 待确认的样式优化。
- 客户正在看的临时功能。

但这些内容不能自动进入生产。

## 四、部署到生产环境

当用户说“只把这条新闻部署生产”“生产只更新这条新闻”时：

1. 先确认 `main` 是当前生产真实版本。
2. 不合并整个 `release`。
3. 只 cherry-pick 本条新闻相关提交到 `main`。
4. 检查 `main` 的 diff，只允许出现新闻相关文件。
5. 本地构建或在生产服务器构建。
6. 部署生产。
7. 检查生产地址：
   - `http://103.107.88.249/`
   - `http://103.107.88.249/newsDetail/<id>`

生产上线前必须确认：

- 有新新闻标题、摘要、日期和详情。
- 没有误带演示功能。
- 如果这次只上线新闻，生产资源中不应出现 `carousel-toggle`、`back-to-top` 等无关功能关键词。

## 五、新闻内容规则

### 1. 内容必须以用户提供材料为准

- 标题、日期、图片、正文必须来自用户提供的 Word、截图或明确文字。
- 不要自由发挥。
- 不要补写背景。
- 不要润色成新事实。
- 不要擅自删改新闻内容。
- 如果用户只说改新闻时间，就只改新闻时间，不改正文。
- 如果用户只说改标题，就只改标题，不改正文。

### 2. 首页新闻只保留 3 条

首页新闻来自 `newsListIndex`。

新增新闻后：

- 新新闻放第一条。
- 后面保留日期最新的两条旧新闻。
- `newsListIndex` 仍然只能有 3 条。
- 首页摘要字段使用 `content`。

### 3. 新闻列表按日期倒序

新闻列表来自 `newsList`。

要求：

- 按日期倒序插入。
- 列表摘要字段使用 `desc`。
- 不要只按 `id` 排序。

### 4. 日期格式统一

统一使用：

```text
YYYY-MM-DD
```

例如：

```text
2026-07-24
```

如果用户只给“7月24日”，必须结合用户说明或文件标题判断年份；不确定时先问用户。

### 5. 简体和繁体必须同步

新增新闻时必须同时更新：

- `zh-CN.json`
- `zh-TW.json`

繁体内容要与简体含义一致，不要漏段。

## 六、每次新增新闻后的核对清单

新增完成后至少确认：

- `newsList` 有新新闻。
- `newsListIndex` 有新新闻且仍为 3 条。
- `newsDetail.vue` 有对应 `id` 的标题、日期和正文分支。
- 简体详情页正常。
- 繁体详情页正常。
- 首页摘要不为空。
- 新闻正文没有被擅自修改。
- 本地或目标环境页面可访问。
- 生产部署时没有带入演示环境的无关功能。

## 七、推荐给 Codex 的执行顺序

以后新增新闻时，Codex 应按以下顺序执行：

1. 先读取本文档。
2. 解析用户提供的 Word、图片或正文。
3. 盘点当前最大新闻 `id` 和标题/正文编号。
4. 修改简体、繁体、详情页和必要图片。
5. 本地运行给用户确认。
6. 用户确认后，提交到 `develop`。
7. 需要演示时，合并到 `release` 并部署演示。
8. 需要生产时，只挑新闻相关提交到 `main` 并部署生产。
9. 部署后检查目标环境页面和资源关键词。

## 八、当前已确认的分支规则

截至 2026-07-24：

- `main` 已调整为生产专用版本。
- `release` 是演示版本。
- `develop` 是开发版本。
- 生产服务器部署脚本固定拉取 `origin/main`。
- 演示服务器应固定使用 `origin/release`。

不要让生产服务器直接部署 `release`。
